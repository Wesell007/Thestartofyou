# Mobile principles (390 px), derived from the five concepts

1. **Composed, not squeezed.** Every concept re-orders and re-sizes at 390 px: asides move below bodies, two-column spreads become document order, splits stack image over text, washes become full-width bands, the masthead becomes wordmark + Menu, signed-in surfaces gain a five-tab bar.
2. **Type scale.** Display 44 → 30, headline 48 → 32, section 30 → 24, deck 21 → 19, body 19 → 17, UI 16, labels 12; display tracking eases from 0.14em to 0.10em. Long spaced-cap titles may wrap to two lines; long editorial headlines use sentence case so they never become a capital wall.
3. **Reading.** Body never below 17 px; measure is the column; line-height 1.6; gutters 20 px.
4. **Touch.** All controls ≥ 44 px; the ask row wraps so the field is full width and the Voice/Ask controls sit beneath; radio rows are full-width labels; code inputs 92 px.
5. **Keepsake devices on mobile.** Frames are never rotated; washes keep their soft radius but span the column; ruled fields keep 36 px lines; the size row is one inline line.
6. **Art.** Corner artwork appears only where Rule 2 allows and is reduced or hidden on mobile when it would touch text (the homepage hides the top-left branch crop).
7. **Docked controls.** The Companion ask dock and the app tab bar are sticky at the bottom in a real screen; in the stacked review files they are static so captures are honest.
8. **Chapter openers** at stage transitions are full-screen, tap to continue, and respect reduced motion.
9. **Shared with the future app.** Tokens, type roles, header pattern, prompt block, photo frame, urgency notice, Companion column, chapter opener; only navigation chrome differs.
10. **Zoom and reflow.** Layouts are single-column fluid at 390 px, so 200 % zoom reflows without horizontal scroll (to verify at implementation).
