# Phase 40A — Priority roadmap

Five hypotheses tested: (1) Journey continuity engine, (2) Permissioned context and memory, (3) Visible trust, (4) Answer → action, (5) Journal/memory continuity.

Result: 1 and 2 merged (memory has little value without continuity and a visible "what we use" surface, and memory alone is an expected category feature). 3 moved first. 5 kept but last. Four priorities, in order. Nothing here is started.

## 1. Visible context and trust
- User problem: "Why should I trust this, and should I talk to a person instead?"
- Why it matters: every later layer (memory, action, journal awareness) needs a place where people can see what an answer used.
- What exists: safety routing (#12), source trust line and links (#18), saved-journey next actions (#14), structured article sources (#29).
- Missing: "based on your saved week/age" explanation, source type labels, when to seek help presented consistently, freshness for policy content.
- Dependencies: none new in data; copy review; no grounding change required for the smallest version.
- Risks: implying review or grounding that does not exist (must follow the claims registry).
- Smallest useful version: one quiet line under answers stating what context was used (page area, saved stage) and the source type, using existing data only.
- Unlocks: memory release, journal awareness, honest About copy.

## 2. Answer → action into existing tools
- User problem: "I know the information but not what to do."
- Exists: questions for midwife, appointments, hospital bag, birth plan, reminders (#38, #39).
- Missing: any path from a Companion answer or article into those tools (#43).
- Dependencies: signed-in state; toolkit tables already exist.
- Risks: turning an urgent situation into a to do; RED/CRISIS answers must offer no action.
- Smallest: "Add to questions for my midwife" on eligible GREEN pregnancy answers.
- Unlocks: saved answers, appointment preparation, reflection prompts.

## 3. Continuity across transitions, with permission
- User problem: "I'm moving into a new stage and don't want to start over."
- Exists: pregnancy → first year transition and kept chapter (#34, #37); memory and history built but OFF (#20, #21).
- Missing: TTC → positive test → pregnancy handoff without re-entry; a controlled memory release.
- Dependencies: privacy/legal approval for memory; loss-aware copy.
- Risks: surveillance feel; carrying forward context after pregnancy loss.
- Smallest: offer to start a pregnancy journey from the TTC journey using dates already saved, with explicit confirmation.
- Unlocks: "tell us once", later memory release.

## 4. Journal keeping continuity
- User problem: "I want to keep this."
- Exists: physical journal (#10), digital reflections/photos (#32, #33).
- Missing: export/print (#35), physical bridge (#36).
- Dependencies: storage, data portability design, product packaging.
- Risks: media privacy; claims ahead of integration.
- Smallest: private export of one chapter's reflections and photos.
- Unlocks: credible "guidance helps you live it, the journal helps you keep it".

Rejected as standalone priority: permissioned memory on its own (expected category feature, E3; high privacy cost without #1).
